## 2026-08-28 - [Authentication Optimization] **Learning:** [Django auth backend retrieves user via `get_by_natural_key()`. If an application serializer such as DRF SimpleJWT's `LoginSerializer` needs to traverse a foreign key like `user.client` for token generation, it causes an N+1 query problem during the authentication process.] **Action:** [Override `get_by_natural_key()` in the custom user manager to append `.select_related('client')` in order to fetch foreign keys in a single query and eliminate the extra database hit.]

## 2026-09-19 - [Admin Action Memory Optimization] **Learning:** [Django admin actions pass the full selected queryset. If an admin selects thousands of items (e.g., 'Select all 50,000 users'), a simple 'for obj in queryset:' loop evaluates the entire queryset and loads all instances into memory simultaneously, potentially causing OOM errors on large tables.] **Action:** [Always use '.iterator()' when looping over querysets in admin actions (or any bulk processing task) to stream results from the database in chunks and keep memory usage flat.]
