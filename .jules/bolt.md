## 2026-08-28 - [Authentication Optimization] **Learning:** [Django auth backend retrieves user via `get_by_natural_key()`. If an application serializer such as DRF SimpleJWT's `LoginSerializer` needs to traverse a foreign key like `user.client` for token generation, it causes an N+1 query problem during the authentication process.] **Action:** [Override `get_by_natural_key()` in the custom user manager to append `.select_related('client')` in order to fetch foreign keys in a single query and eliminate the extra database hit.]
